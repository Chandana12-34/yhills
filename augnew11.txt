CLASSIFICATION HIERARCHY RULES:

The classification follows this hierarchy:

Issue Type → Category → Sub Category

Use the taxonomy according to the following rules:

1. If Issue Type is "Application Support":
   - Category MUST be either "Functional Support" or "Technical Support".
   - If Category is "Functional Support", select the appropriate Sub Category from the Functional Support taxonomy.
   - If Category is "Technical Support", select the appropriate Sub Category from the Technical Support taxonomy.

2. If Issue Type is "Application Issue":
   - Select the appropriate Category from the Application Issue Categories.
   - The selected Category is also the applicable Sub Category for Application Issue tickets unless a more specific sub-category is explicitly defined in the taxonomy.
   - Examples include:
     "Workflow Exception"
     "KYC Escalation Form"
     "Screening Issue"
     "Performance and Slowness"
     "User Interface"

3. Do NOT independently choose Category and Sub Category.

4. Category and Sub Category must belong to the selected Issue Type.

5. Never return "Other" for both Category and Sub Category when the ticket contains enough information to select a specific classification.

6. "Other" should only be used when the ticket genuinely cannot be mapped to any specific allowed classification.

7. Do not invent, rename, or create classification values.

8. Prefer the most specific classification supported by the ticket details.

9. Use the ticket's Short Description, Description and Comments together when determining the classification.

10. The classification must represent the actual issue described in the ticket, not merely keywords appearing in the text.
